# 0.6.2-rc.2 validation

Baseline: the actual previous consolidated 0.6.2-rc.1 JAR, SHA-256 `da93acd70fd14ef1ab2c974e44e7eadea1806db6fa52a921d2cedcf07405492e`. Preservation checks cover every previous entry except version metadata, EncounterRewards, its opt-in CombatChecks fixture and the native entity loot table. The new DelayedDeathLoot class owns delivery timing. Boss combat, movement, animations, sounds, summoning, five recipes, approved Core item/model/icon/tooltip, gear abilities/assets and LC Core are unchanged byte-for-byte. See the final entry comparison and checksums.

Build: Java 21.0.6, Minecraft 1.21.1, NeoForge 21.1.259, Gradle 8.14.3, ModDevGradle 2.0.148; cached/offline dependencies. Native model parser checks for the unchanged Core and Fragment remain included.

Dedicated-server probes load the installed JAR rather than development main classes. Existing equipment/crafting checks run with the reward fixture updated for queued delivery. The loot probe samples 10,000 deterministic native-table rolls, checking guarantees, bonus rates/co-occurrence, equal weapon-family and armor-slot selection, compatible max-level gear enchantments, enchanted-book storage/glint and stack limits. Identical seeds at Luck 0 and Luck 100 retain identical results.

A native lethal hit verifies items/XP are absent at death. The method-driven death test serializes/reloads a corpse at tick 200, verifies identical pending stacks/components, advances through tick 409 with no payout, and verifies the exact committed item stacks and one 1,000–1,500 XP total at tick 410. Later ticks and paid-state reload do not duplicate payout. The delayed Core is collected into a test inventory. Existing bridge-contract death-time qualification checks remain, with no Core bonus reroll during the delay.

A separate live scheduler probe uses ordinary server/entity ticks, without synthetic tick events or manual entity ticking. It kills a Harrower, verifies no early Core/XP, observes payout at native death tick 410, and observes another 20 server ticks without duplication. Test-only forced chunk tickets and probe classes are excluded from the installable JAR. Require the explicit pass markers in the evidence; process exit alone is not sufficient.

Limits: no rendered client or human gameplay test is claimed. The new payout is tied to the existing server death clock; final visual alignment to the crumble should be checked in-game. NBT reconstruction/resumption is narrower evidence than a full live server restart/chunk-unload test. The optional installed-LC behavior remains API-audited/bridge-contract tested, not tested in the full 200-mod pack. Normal Minecraft save guarantees apply; no cross-file crash/rollback transaction is claimed. Third-party item-spawn rejections retry during the corpse's remaining lifetime; forced removal or persistent external cancellation can prevent delivery.
